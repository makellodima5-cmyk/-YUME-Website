# Хранилища браузера и сторонние сервисы YUME

**Дата аудита:** 22 октября 2026 г.  
Документ отделяет текущее поведение кода от интеграций, которые владелец планирует к запуску.

## Подтверждено в коде

| Механизм / сервис | Назначение | Ограничение |
|---|---|---|
| localStorage yume-language | Язык интерфейса | Локально в браузере |
| localStorage yume-theme | Тема оформления | Локально |
| localStorage yume-cookie-notice-acknowledged | Запоминает закрытие баннера | Не является выбором категорий |
| localStorage yume-favorite-anime-v1 | ID избранных тайтлов | Нет серверной синхронизации |
| localStorage yume-watchlist-anime-v1 | ID тайтлов в списке | Нет серверной синхронизации |
| Cloudflare D1 | Каталог; код также предусматривает таблицы аккаунтов и сессий | Текущая архитектура, целевой план — перенос |
| Shikimori API | Серверный источник метаданных | Состав и доступность зависят от API |
| YouTube youtube-nocookie.com | Встроенный трейлер, если доступен ID | Браузер соединяется со сторонним сервисом |
| VK ID / Яндекс ID | Backend OAuth-код и регистрация | Кнопки UI отключены; production-вход не подтверждён |
| Яндекс Метрика | В проверенном коде не обнаружена | Целевая интеграция; счётчик нужно установить |

## Cookie-баннер

Сейчас баннер сообщает, что продолжение использования означает согласие с политикой персональных данных/cookie, и имеет одну кнопку «Хорошо». Нажатие записывает yume-cookie-notice-acknowledged=true в localStorage. Это только отметка о закрытии уведомления: код не хранит отдельное решение об аналитике и не реализует блокировку аналитических запросов.

**Целевой интерфейс, запрошенный владельцем:** кнопки «Принимаю» и «Отклоняю». Рекомендуемая логика перед запуском:
- при принятии включать согласованный набор аналитики;
- при отказе не загружать счётчик Метрики и связанные необязательные аналитические запросы;
- позволять пользователю пересмотреть выбор через доступные настройки/ссылку на сайте;
- не смешивать необходимые технические механизмы с аналитикой;
- не считать простое продолжение использования сайта согласием.

Эта логика пока не реализована. Документ не должен создавать впечатление, что управление согласием уже работает.

## Яндекс Метрика — целевой план

Официальная документация Яндекса указывает, что Метрика может использовать cookies и localStorage для браузерных идентификаторов. Фактический перечень данных зависит от параметров счётчика и включённых функций.

Стартовая конфигурация, которую следует подтвердить с владельцем:
- IP-маскирование включено;
- Вебвизор выключен;
- UserID, email, никнейм, дата рождения и содержимое форм не передаются;
- автоматические цели не включаются до отдельной проверки;
- счётчик не запускается до принятия аналитики, если владелец утвердит такой механизм согласия.

Официальные источники:
- https://yandex.ru/support/metrica/ru/general/cookie-usage.html
- https://yandex.ru/support/metrica/ru/general/ip-masking
- https://yandex.ru/support/metrica/ru/general/confidential-data

## OAuth

Код запрашивает scope vkid.personal_info для VK ID и login:info для Яндекс ID. В пользовательской таблице YUME код предусматривает хранение внутреннего ID, провайдера, стабильного ID пользователя провайдера, даты рождения, времени/версии согласия. Не указывать имя, email, телефон или аватар как сохраняемые YUME, пока это не реализовано и не подтверждено в фактической конфигурации.

## Проверки после переезда

Провести скан сетевых запросов в чистом браузере до выбора, после принятия, после отказа и после изменения выбора. Для каждого домена-получателя зафиксировать данные, цель, правовое основание, сроки, cookies/localStorage и место обработки. Отдельно проверить OAuth, YouTube, Shikimori, серверные логи и почтовый сервис.
