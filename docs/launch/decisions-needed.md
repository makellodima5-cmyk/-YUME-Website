6. **Уведомление РКН:** по сообщению владельца не подавалось. Владелец планирует разобраться с подачей перед публичным запуском. ## C. Инфраструктура, данные и удаление

8. **Целевой хостинг:** Selectel в РФ, но конкретный продукт/runtime не выбраны.
9. **Текущая конфигурация:** Cloudflare Workers и D1. Неизвестно, останется ли Cloudflare в роли DNS/CDN/WAF/proxy после миграции.
10. **Целевая БД и backup:** не выбраны. Установить регион БД, backup, логи, договорное поручение на обработку и контроль доступа.
11. **Сроки хранения:** не выбраны. Утвердить сроки для аккаунта, истории просмотра, избранного, сессий, журналов и резервных копий.
12. **Удаление аккаунта:** целевое требование владельца — удалять всю информацию пользователя. Нужно определить и реализовать точный охват: профиль, внешний provider ID, никнейм, история, избранное, сессии, кэши и резервные копии. Не обещать немедленное удаление из всех слоёв, пока механизм не существует и не проверен.
13. **История просмотра:** владелец подтвердил, что история просмотра входит в целевую модель аккаунта. В кодовой документации функция пока отмечена как заглушка/незавершённая; реализовать серверное хранение и проверить удаление вместе с аккаунтом.
14. Код регистрации ранее запрашивал полную дату рождения и предусматривал её хранение. Подтвердить, остаётся ли дата рождения необходимой для возрастной защиты; минимизировать данные и согласовать срок хранения.

## D. VK ID / Яндекс ID

15. **Набор данных от провайдера:** по решению владельца использовать только стабильный ID для привязки аккаунта; никнейм вводит сам пользователь. Это целевая настройка, требуется проверить scopes и фактические записи базы.
16. Провести end-to-end тест с production callback URI, ключами и целевой БД. Перенос на Selectel сам по себе не включает кнопки OAuth.
17. Яндекс публикует специальную инструкцию для владельцев сервисов без гражданства РФ: может потребоваться обращение в поддержку для проверки аккаунта OAuth. Проверить процедуру для личного аккаунта владельца: https://yandex.ru/dev/id/doc/ru/confirm-account.
18. Проверить текущие VK ID endpoints и версии SDK на официальной документации до включения.

## E. Метрика и cookie

19. **Метрика:** планируется базовая аналитика посещаемости, но в проверенном коде счётчик не обнаружен.
20. **Согласие:** решение владельца — запускать Метрику только после явного согласия на аналитику. При отказе блокировать счётчик и необязательные аналитические запросы; дать возможность изменить выбор позже.
21. Реализовать вместо текущей кнопки «Хорошо» два варианта «Принимаю» / «Отклоняю». Текущий баннер не реализует consent management.
22. До подключения согласовать и фактически проверить IP-маскирование Метрики, Вебвизор (по плану выключен), автоматические цели, UserID и отсутствие передачи идентификаторов/никнейма/даты рождения/содержимого форм. Рекомендация для первой версии — маскирование IP включить, Вебвизор выключить, пользовательские идентификаторы не передавать.
23. Утвердить перечень необходимых cookie/localStorage и срок хранения записи выбора. Не считать обычное закрытие уведомления согласием.

## F. Несовершеннолетние, возрастная защита и контент

24. **Аудитория:** включает несовершеннолетних.
25. **Контент 18+:** целевое решение владельца — блокировать его для несовершеннолетних. Нужно определить источник возрастных меток, механизм проверки возраста, поведение для незалогиненных пользователей и правила для общего каталога. Код должен реально блокировать страницы/обложки/трейлеры, где это необходимо; одного текста в Политике недостаточно.
26. Определить, могут ли несовершеннолетние регистрироваться и пользоваться общей частью сайта, если 18+ материал для них закрыт.
